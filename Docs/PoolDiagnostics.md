# 개발용 오브젝트 풀 진단

PIE 또는 Development 빌드에서 콘솔(~)에 다음 명령을 입력한다

```text
rl.Pool start
rl.Pool snapshot
rl.Pool stop
```

`start`는 측정 횟수를 초기화하고 새 측정을 시작한다. 게임 진행이나 풀에 보관된 객체는 초기화하지 않는다

`snapshot`은 현재 객체 수와 측정 횟수를 기록한다. `stop`은 횟수 집계를 멈추고 마지막 결과를 기록한다

Output Log에서는 `LogRLPoolDiagnostics`로 확인할 수 있다. 측정 구간마다 별도의 UTF-8 CSV 파일이 `Saved/Profiling/PoolDiagnostics`에 저장된다. Shipping 빌드에서는 명령과 진단 서브시스템을 사용할 수 없다

대상 풀은 `Projectile`(투사체), `Enemy`(적), `RollAfterimage`(구르기 잔상), `ProjectileEffect`(투사체 소멸 파편 효과)이다. 한 번도 등록되지 않은 풀은 출력하지 않는다

`ProjectileEffect`는 액터와 내부 파편 컴포넌트를 보관하며, 같은 기본 머티리얼에서는 동적 머티리얼도 재사용한다. 기본 머티리얼이 바뀌면 동적 머티리얼은 새로 만든다. 통계는 액터 단위이며 내부 컴포넌트·머티리얼 할당 횟수는 포함하지 않는다. Niagara 풀과 다른 폭발·적 사망 효과는 이 항목에 포함하지 않는다

소멸 효과를 확인하려면 `start` 후 탄환이 여러 번 소멸하도록 플레이하고, 게임이 계속 진행되는 상태에서 마지막 효과 종료 후 `stop`을 입력한다. `ProjectileEffect`의 `reused` 증가, `released` 증가, 종료 시 `active=0`을 확인한다. 동시 효과 수가 기존 보유량을 초과하면 `created`가 증가하는 것이 정상이다

- `active` / `inactive`: 기록 시점의 유효한 활성 객체 수 / 풀에 보관된 비활성 객체 수. 페이드아웃 중인 객체는 실제 풀 반환 전까지 활성 객체로 집계한다
- `peak_active`: 측정 구간의 최대 동시 활성 객체 수. 측정 시작 전에 이미 활성화된 객체도 포함한다
- `created`: 측정 중 풀에서 새로 생성한 객체 수. 사전 생성(프리워밍)도 포함한다
- `reused`: 측정 중 비활성 풀에서 꺼내 재사용한 횟수
- `acquired` / `released`: 객체 획득 횟수 / 활성 객체를 비활성 풀로 반환한 횟수. 같은 객체의 중복 반환은 추가로 집계하지 않는다
- `elapsed_wall_seconds`: 일시 정지 시간도 포함한 실제 경과 시간(초)
- `state`: 측정 중이면 `running`, 측정 중이 아니면 `stopped`

객체 수는 월드별·풀 종류별 합계이며, 블루프린트 클래스별로 나누지는 않는다

외부에서 파괴된 액터는 객체 목록에서 제외한다. 파괴는 풀 반환으로 집계하지 않는다. 유효하지 않은 획득 요청과 중복 반환은 횟수를 증가시키지 않는다

`start`를 다시 실행하면 독립된 측정 구간과 파일을 만든다. `stop` 이후에도 현재 객체 수는 변할 수 있지만 생성·재사용 등의 횟수 집계는 멈춘 상태로 유지된다

진단 기능은 프레임 프로파일러가 아니며, 개발 빌드에 CPU·메모리 부하를 추가한다

## 포트폴리오용 측정 자료 수집

비교할 자료는 빌드·맵·라운드·해상도·그래픽 설정·카메라·증강 선택·플레이 시간을 가능한 한 동일하게 맞추고, 해당 조건을 CSV와 함께 기록한다

시작 시 객체 생성을 확인하려면 프리워밍 전에 측정을 시작한다. 전투 중 재사용을 확인하려면 프리워밍 이후에 시작한다. 어느 구간을 측정했는지 명확하게 표기한다

난수가 사용되는 전투는 라운드 번호가 같다는 이유만으로 동일 조건의 결정적 벤치마크가 되지는 않는다

프레임 시간과 메모리 할당 분석에는 Unreal Insights를 별도로 사용한다. 이 진단 수치만으로 프레임 성능이 향상되었다거나 풀링을 사용하지 않을 때보다 빠르다고 주장해서는 안 된다

## 자동 회귀 테스트

`ReflectionLab.Diagnostics.ProjectileEffectPoolTenCycles`는 소멸 효과의 10회 재생에서 동일 액터·파편 컴포넌트·동적 머티리얼 재사용, 수명 종료 반환, Tick·위치 초기화, 중복 반환 방지, 풀 고갈 시 생성과 무효 요청을 검사한다. 화면의 시각적 정상 여부나 Niagara 풀 검증을 대체하지 않는다

`ReflectionLab.Diagnostics.PoolLifecycleTenCycles`는 실제 투사체·적·잔상 객체의 획득 → 상태 변경 → 반환을 10회 반복한다

다음 항목을 검사한다

- 동일 객체 재사용
- 반사 상태·랠리 피해 이력·패리 시도 제외 정보·반사벽 튕김 상태 초기화
- 소유자·공격 주체 재설정과 충돌 복원
- 적 체력 복원과 지원 보호막 상태 초기화
- 잔상 수명 종료·풀 반환·소유자 해제
- 증강 이력 초기화와 체력 초기화 API의 반복 호출
- 통계의 정확성, 중복 반환 방지, 풀 고갈 시 신규 생성
- 독립된 측정 구간과 측정 중지 후 횟수 집계 정지
- 외부에서 파괴된 객체의 집계 제외

기존 `ReflectionLab.Experiments` 테스트는 지원 유닛 무효화, 장판 정리, 실제 투사체 반사·피해, 웨이브 간 카메라 유지와 라운드 종료 시 복원을 검사한다

기존 `ReflectionLab.Combat.SpecialProjectileReflection` 테스트는 특수탄 반사 규칙을 검사한다

이러한 객체·컴포넌트 초기화 테스트는 메뉴·맵을 포함한 전체 게임 재시작 10회나 패키징 빌드 플레이 검사를 대체하지 않는다. 해당 항목은 별도로 확인해야 한다
